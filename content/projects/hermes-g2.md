I run Nous Research's open [Hermes Agent](https://github.com/NousResearch/hermes-agent) on a Mac mini, and I wanted a way to check on it and approve tool calls from Even G2 smart glasses without pasting the master API key into a phone or wearable app. If someone picks up your phone, they shouldn't inherit full control of your agent.

Hermes G2 is that private client and bridge. It's a personal setup rather than an official client, and I haven't run it on physical G2 glasses yet, so this write-up covers the code and the bridge design.

## Keeping the master key on loopback

Everything hinges on one constraint: Hermes's master API key never leaves the Mac mini.

```text
Even G2 glasses  ->  Even Hub app  ->  Tailscale Serve  ->  bridge (127.0.0.1)  ->  Hermes (127.0.0.1)
```

Both Hermes and a small FastAPI bridge bind strictly to `127.0.0.1`, leaving Tailscale Serve as the only route in from outside the machine.

New devices pair with a one-time six-digit code generated by `hermes-g2-bridge pair hub`. The client exchanges that code once for a device ID and a random credential, and the bridge stores only an Argon2 hash so a leaked database copy won't grant access. Scopes are locked by device type: the glasses can read sessions, send prompts and audio, stop runs and answer approvals, while device management and audit logs stay off-limits. Only the Android fallback app can revoke a device, leaving other paired devices untouched.

## Idempotent actions and capability checks

Wireless links drop, and a client that misses a reply will retry. Applying a tool approval twice is a real fault, so every action carries an `idempotencyKey` of at least 8 characters:

```json
{
  "kind": "approveOnce",
  "deviceId": "<device id>",
  "idempotencyKey": "<unique key>",
  "sessionId": "<session id>",
  "runId": "<run id>",
  "createdAt": "2026-08-07T10:15:00Z",
  "payload": { "requestId": "<request id>" }
}
```

The bridge stores a SHA-256 hash of the body under `(deviceId, idempotencyKey)`. An exact retry receives the stored response without re-running; reusing the same key with a different payload returns `409`. Out of 17 action kinds, the five that stop a run or answer an approval must name both `sessionId` and `runId`, and the bridge rejects approvals that are stale or already resolved. Persistent or sensitive choices add a second confirmation screen on the glasses, and voice input can continue a conversation but can never grant a permission.

Before showing controls, the bridge reads Hermes's advertised capabilities (and refreshes them after a restart). Session edits stay off unless Hermes advertises native sessions, streaming and history; approve and stop buttons stay hidden unless `session_run_control` and `session_approval_response` are advertised. A patch in `patches/` adds session run control to Hermes through its existing Runs API under that same gate.

## Cursor replay, local Whisper and 16 shades of green

To avoid losing updates over flaky Bluetooth links, the bridge writes all 19 event types (`run.started`, `tool.completed`, `approval.required`, etc.) to SQLite with a monotonically increasing cursor. When Even Hub reconnects over WebSocket, it sends the last cursor it saw, replays missed events in order, then streams live updates and acknowledges progress.

Recorded audio arrives as signed 16-bit PCM at 16 kHz (up to 45 seconds). The bridge rejects near-silent clips, transcribes locally with a Whisper binary on the Mac mini (30-second limit), and deletes the temporary file—no audio leaves for a hosted speech API.

The G2 display is 576×288 pixels in black and 16 shades of green, so brightness carries the whole layout hierarchy: 100% for actionable prompts, 72% for content, 45% for metadata and 24% for rules. The screen always yields to whatever is most urgent: approvals first, then failures, then active checkpoints, then final replies. Every accepted, rejected and failed action goes into an audit log that scrubs secrets to `<redacted>` and home paths to `<private-path>`.

## Inside the repository

- `services/bridge`: FastAPI bridge with cursor log, pairing, audit log and local Whisper STT.
- `apps/hub`: React and TypeScript Even Hub app on the official Even Hub SDK.
- `apps/android`: Kotlin and Compose fallback controller with a persistent event service.
- `packages/protocol`: versioned JSON Schema for every message.
- `packages/hermes-plugin`: plugin observing Hermes lifecycle events.
- `deploy`: `launchd` and Tailscale files for the Mac mini.

## Limits

Hermes's web and terminal clients (and normal phone chat apps) give you a keyboard and a full screen; glasses only make sense for hands-free glances, quick approvals, an isolated API key and cursor replay.

Until I test on physical Even G2 glasses, Bluetooth timing, microphone hand-off, power behaviour, gestures and real display legibility are all unchecked. The Android app also hasn't been tested against Doze, process death or reboots, and I have no end-to-end latency numbers yet. Standing up the full setup requires a Mac mini running Hermes, Tailscale Serve, Even Hub and root-owned launch services, and the repo has no public licence since it's built for my own machine.

You can still boot the bridge on its own to inspect the code:

```sh
git clone https://github.com/hridaya423/hermes-even-g2
cd hermes-even-g2/services/bridge
uv sync --extra dev
uv run hermes-g2-bridge migrate
uv run hermes-g2-bridge serve
```
